Core rules

Edge‑first system: trade at state nodes; first‑touch = rejection; acceptance → chase the magnet.

State map example — annotate nodes and magnets.

How it works

  • Map States → Nodes → Magnets before placing risk.
  • Green→Red approach: base case = rejection short on the first touch of the red node.
  • Red→Green approach: mirror — rejection long on first touch of the green node.
  • Acceptance through a node ⇒ chase toward that state's magnet.
  • Stops live just beyond the node (outside the state change).
  • After a full traversal to the far end node, interior bars become Flat on the next pass.

Core terms

Keep language strict: States, State nodes, End nodes, and State intensity (Magnet).

Definitions

  • State — contiguous run of same‑color bars. Reds → Red state; Greens → Green state.
  • State node — boundary where a green state meets a red state (interaction point).
  • End node — the outermost bar of a state at a state node (prime entry + tight risk).
  • State intensity (Magnet) — longest/strongest bar inside a state; once accepted, price gravitates to it.
Label your ladder once per session and reuse across notes.

Mapping process

Mark states, locate nodes, identify magnets, and record distances from spot.

Steps

  1. Identify the nearest green/red states around spot.
  2. Mark the state nodes (where states touch).
  3. Inside each state, mark the magnet (highest state intensity).
  4. Note distance from spot for each magnet (helps with pathing and RR).

Interaction rules

First touch favors rejection; acceptance means you are inside that state → expect pull to its magnet.

Node logic

  • Green→Red: first‑touch at the red node = rejection short (base case).
  • Red→Green: mirror — rejection long at the green node.
  • Acceptance (close + continuation through the node) ⇒ expect traversal toward the magnet.
  • First touch has the highest expectancy; re‑tests are lower‑quality unless weaker.
Rejection vs acceptance — pick the correct side and manage to the magnet.

Execution playbooks

Edges only: enter at nodes. Stops are beyond the state change. Targets = mid‑state → opposite node → magnet.

Short at Red state node (from green)

  • Trigger: clean tap + stall · rejection wick · micro BOS (break of last HL).
  • Stop: a few ticks above the red node.
  • Targets: mid‑state → opposite node → red magnet.
  • Acceptance: if accepted into red, chase short → red magnet.

Long at Green state node (from red)

  • Trigger: clean tap + stall · rejection wick · micro BOS (break of last LH).
  • Stop: a few ticks below the green node.
  • Targets: mid‑state → opposite node → green magnet.
  • Acceptance: if accepted into green, chase long → green magnet.

Risk System Methodology

Stops beyond nodes, clear invalidations, disciplined adds, and when not to fade stacked states.

Risk mechanics

  • Stops: always just beyond the state change (outside the node).
  • Invalidate on deep accepted penetration or three consecutive impulse prints through a thick node.
  • Adds: re‑tests that hold with weaker subsequent prints only.

Guardrails

  • Do not short a stacked Green state without a prior transition.
  • Either wait for a full traversal to spend the state (next pass = Flat) or a clean Red node above.

Pre‑trade checklist

  1. Active states, nearest node, destination magnet mapped.
  2. Approach side and touch count (first vs re‑test) noted.
  3. Destination state already spent? If yes, interior is Flat on next pass.
  4. Trigger present: stall · rejection wick · micro BOS.
  5. Stop just beyond node; targets = mid‑state → node → magnet.
  6. News/vol envelope acceptable; if tier‑1 risk, pass or size down.
